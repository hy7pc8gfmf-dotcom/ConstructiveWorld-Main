## 一、案由

现行认证铁律：认证面每一 `.vo` 件，每一认证轮次，全量送 coqchk 内核验算；
全绿方判绿。此律在树规模增长（Main 现认证面 876 顶层件·档案实测 848 件字节
与上次全绿运行全等·沙箱对账 20261029 且打磨员 20261030 复核同值 unchanged=848
changed=0）与轮次频度上升下产生纯重复验算：当轮重验字节未变件不产生任何新
判定信息（论证见 §四）。修宪目的：把「验算」与「内容」解绑——验算跟随内容
变化，而非跟随轮次——同时以机械断言保证认证强度一分不减。

**实测经济性（Set 床·本条修订的直接动因数据）**：Set Live 树 90 件全量建档
后，一轮全树逐件哈希对账实测 **0.2 秒**（测试报告 T1 20261030）；打磨员
20261030 复核 **0.1 秒**、Main 848 件 **0.9 秒**——对账动作与验算动作的代价
差 5 个数量级以上（对照 Main 认证炉 14h 级·#301 实测 coqchk 段 14h09m），
「逐轮全量重验字节未变件」的纯重复部分由此可机械消去而不触判定面。

## 二、修正条款（本法四句，替代原「逐轮全量送检」单句）

**第一条（全量验算律）** 任何被认证承载的内容（`.vo` 字节串），在其存续期内
必须**至少被 coqchk 全量内核验算一次**；认证的原始出处只能是全量绿运行
（认证面无跳过清单的运行）。禁止从任何未经全量验算的字节直接制造认证条目。

**第二条（哈希继承律）** 已验内容在其后任意轮次中，若当轮现算哈希与档案
条目**字节全等**（sha256 与字节数双双相符），其认证得凭哈希继承，该轮免列。
继承判据一律当轮现算：禁缓存、禁 mtime、禁任何 stat 元数据入判
（契约原文：coqchk_attest.py:17-18「mtime、任何 stat 元数据均不入哈希、
不入档案」）。

**第三条（偏离必检律）** 内容偏离——任一字节改、增、删，即 changed / added /
removed——继承当场断，偏离件**必须当轮送 coqchk 全量验算**。无例外、无豁免、
无人工白名单。跳过面与送检面的划分（并集=认证面、交=空）由机器断言把守，
违者红（fail-loud）。

**第四条（强度不减律）** 第一至三条作为整体生效，其生效前提是 §四强度论证
成立；论证若被推翻，本案自动失效，认证法回滚至「逐轮全量送检」原句。
继承永远不得成为弱于重验的替代（论证表明二者在判定上不可区分，§四命题 2）。

## 三、定义与从法

**定义（认证面）** 当轮 vo 树根（非递归）加档案键所涉子目录中的 `.vo` 件，
`_` 前缀件除外（CI#46 教训，`parallel_chk.sh:116-118` 在案）。
**定义（档案）** `cw.attest/v1` 契约文件：`modules`（键=模块名，值=
`{vo_sha256, size}`）、`tree_sha256`（modules 典范式串列的 sha256，跨运行
可复现，coqchk_attest.py:19-21）、`generated_by`（契约定值
`coqchk green run`）、`schema`。档案结构自洽（tree_sha256 按 modules 重算
相符）是继承合法性的最低机器前提。
**定义（全量绿运行）** 认证面全送检、coqchk 零 lane 失败、gate2 全断言绿之
运行；唯此类运行得铸造或刷新档案条目（建档律）。

**从法一（代际钉从律）** 继承只在同工具链代内有效。代以 coqchk banner 钉定
（Chicken 9.1.0，Main coq.yml:285-286 原文：「COQLIB 钉代防假红」）。跨代档案
继承无效，跨代必须全量重验或重铸档案。
**从法二（降速不降强从律）** 一切档案侧异常——缺席、坏档、契约不符、自洽破
——只许导向全量送检（更慢、更强），禁导向更弱判定。档案侧异常永不红、
永不弱：本条是继承制的安全阀，红只增不减教义（coq.yml:69）在认证态下的
具体化。**代价上界实测**：回退全量的前置对账动作本身为亚秒级纯哈希流读
（Set 90 件 0.1s·Main 848 件 0.9s·打磨员 20261030 实测）——安全阀的开启
代价与全量 coqchk 相比可忽略，故本从法无「因怕慢而绕行」的诱惑面。
**从法三（证据三物从律）** 判绿轮次必须三物同轮落证：日志侧正本（`_chk_all.log`
附页——跳过清单逐件留痕）、哈希侧正本（对账报告 `attest_reconcile.json`）、
断言侧正本（裁定书 `gate2_attest.json`，绿判绑定档案 `tree_sha256` 指纹）。
三物指纹互绑，单方篡改可由另两方交叉暴露。
**从法四（跳过面收窄从律）** 跳过面只许机械收窄、不许机械扩张。v1 收窄：
仅顶层模块可入清单，`Local/` 子目录件维持闭包核验现状。任何扩张跳过面的
改动视同修宪，须另案。

## 四、强度不减论证（第四条生效前提）

**命题 1（确定性公理）** coqchk 判定是输入的确定函数：`verdict = f(vo字节,
工具链代, 旗标)`。内核验算无随机源、无时钟依赖、无环境反馈（同代同旗标下，
同字节必同判定）。此为 coqchk 作为内核复验器的设计语义，亦为本库代际钉
制度（从法一）所依赖的同一公理——本案不新增信任假设。

**命题 2（继承≡重验）** 对字节串 x，若存在历史全量绿运行 h 铸造的档案条目
锚定 x（`vo_sha256=sha256(x)`），且当轮现算复认树内件字节=x，则当轮若对 x
重验，由命题 1 必得与 h 相同的判定（绿）。故「凭哈希继承」与「重验」对同一
输入产生**同一判定**——继承不引入任何「重验可通过而继承不通过」的输入，
反之亦然。继承不是验算的豁免，是验算结论在字节全等约束下的搬运。

**命题 3（偏离必检封闭归纳缺口）** 认证面对字节操作的响应是完备二分：
字节变 → 哈希变 → 跌出继承域 → 落入当轮验算域（第三条，机器断言把守划分）。
字节不变 → 继承域（命题 2 保证等价）。二域并=认证面、交=空、划分当轮现算。
不存在第三域。故任何改变判定面的企图必先改变字节，而改变字节必先进入验算域。
**活体实证（Set 床 20261030）**：#C-M27 回滚（8240b34）在树上遗留 5 件
档案外 vo（BetaLower/Ln2Bridge/Ln2Escape/UpReqIrrationalCriterion/
UpReqLn2Irrational.v），对账即时逐件精确点名 added=5（打磨员实跑）——偏离
无隐身面。

**命题 4（实际验算面只增不减）** 认证态运行的实际内核验算面 ⊇ 送检件闭包
（coqchk 递归本性，`parallel_chk.sh:43-44`：「组内核沿传递闭包整链核验；
跨组共享基座被重复核验=更强保障非缺口」）。继承件若为受检件依赖，仍被重验
——跳过仅免「列为清单成员」，不免「被闭包卷入」。叠加 gate5 二进制检疫
扫全树不因跳过缩小（coq.yml:202-223），认证态的整体防线弱于全量态之处
**为空集**。

**命题 5（与既有指纹纪律同构且更严）** 本库 build 面已实行「`.vo` 新于 `.v`
即跳」的指纹缓存（coq.yml:117-118；CONSTRAINTS.md:99 「fingerprint SKIP
(`.vo` newer than `.v` → skip)」原文在卷复核）。本案把同一纪律延至认证面，
判据从 mtime 新旧升级为**全量内容哈希**——mtime 可失真可绕（touch 即骗过
build 指纹），内容哈希对字节差异完备。故本案认证面判据严格强于既有 build
面判据。

**推论（强度不减）** 全量态判绿 ⟺ 认证面全体验算成立。认证态判绿 ⟺
(当轮验算成立的子集) ∪ (哈希复认=历史绿运行验算内容的子集) = 认证面全体。
两态判绿的语义内容相同（每份内容都在某轮被全量验算且字节至今未变），
认证态仅消去对「字节已证不变」内容的重复验算动作。强度差=空集。∎
