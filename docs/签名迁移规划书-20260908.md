## §2 四类分类：判据与分布

### 2.1 判据（施工席逐件打标时照此执行）

- **(a) 已迁移**：基内或模块内已存在 req 系对应件（§1.6 对账表的 8 件 Id 原件）。施工时**只做消费**（Require + 指名引用），不得重证。
- **(b) 可机械平移**：陈述中 `Id` 仅出现在 R 上的等式位置；证明主体为环代数 rewrite、求和三性质组装、正性/归一化/单调 ≤ 链。Id→req 替换后：每处 `rewrite` ≈ 1 个 compat 桥 + 1 层 `req_trans`；`f_equal`/`congruence` ≈ 1 个 `req_*_compat`。**验证性特征**：该件在 Real 层已有逐 eps 复刻或 real_* 对位（如 `real_rlhf_optimal_eps`@43804 对 `rlhf_optimal`）——复刻经验证照抄结构。
- **(c) 需新分析机器**：满足以下任一：
  1. 证明消费 §1.5 B 类 Variable（需先建"接口桥接引理"或"Real 种子 + req 桥"）；
  2. 唯一性/极小性论证核心步为 destruct + eq_ind 注入消去（req 世界不可用，需 `req_add_cancel_l` 式消去链 + log/inv 单射性）；
  3. iff/当且仅当、严格单调/反单调链、端点夹逼——需 ≤/lt 的 req 兼容传递机器（部分已在 setoid 字段）。
- **(d) 保持双层并行（不迁移）**：
  1. **反例见证件**（`counter_ex_*` 2 件）：陈述本身以 Id 为载体构造反模型，属抽象层的诚实边界证据，迁移反而稀释语义；

## §3 逐件迁移策略（三类模板，施工席按件对号入座）

### 3.1 模板 T1：(b) 类机械平移（覆盖 584 件）

**节骨架**（沿 UpSigMigrate 先例，已四关验证）：

```coq
Section Req<原节名>.
Context {R : Set} {RIS : RealInterfaceEnhancedSetoid R}.
Variable S : Set.
Variable sumf : (S -> R) -> R.                       (* = sum_req_over_S 规格 *)
Hypothesis sum_ext  : forall f g, (forall s, req (f s) (g s)) -> req (sumf f) (sumf g).
Hypothesis sum_add  : forall f g, req (sumf (fun s => plus (f s) (g s))) (plus (sumf f) (sumf g)).
Hypothesis sum_linear : forall a f, req (sumf (fun s => mult a (f s))) (mult a (sumf f)).
Hypothesis sum_pos  : forall f, (forall s, lt zero (f s)) -> lt zero (sumf f).
```
- 优先形态：若目标件只依赖求和三性质而不依赖 `StateSpace`/`SumOver` 类，**直接抄基内 setoid 旗舰件的全称泛化形态**（显式 forall 参数，探针已核验 `attention_is_gibbs_setoid` 形态），不建 Section。
- 语句翻译规则：`Id x y` → `req x y`；`log x` → `log x Hx`（**补正性前提**——唯一系统性的诚实签名变化）；`sum_over_S f` → `sumf f`；`normalized p := Id (Σ p) 1` → `req (sumf p) one`；`lt`/`le` 原样。
- 证明翻译规则：Id 原件每行 `rewrite H` → `apply (req_trans _ _ _ (req_*_compat _ _ _ _ req_refl H) req_refl)` 或直接 compat 槽拆解；`f_equal` → 对应 `req_plus_compat`/`req_mult_compat`/`req_opp_compat`；`rewrite <- H` → `req_sym` 桥（**方向错位最高频，见 §4.1**）。
